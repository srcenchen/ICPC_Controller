# ICPC 机房集控

Go 服务端 + Linux 选手机客户端。管理界面、静态资源均内嵌在服务端，无需单独部署前端。

## 构建与升级

```bash
make build
./server --port 8080 --tcp-port 8081 --p2p-port 48080 --db icpc.db
```

本次升级需要同时更新 **server 和 client**。旧客户端可以继续注册，但不支持新的 SHA-256 分发回执；系统会明确报告需要升级，而不会把未校验的下载记为成功。

升级前请备份原数据库及整个 `data/`。数据库结构会自动迁移。首次升级会更换旧版固定的登录签名密钥，需要重新登录。默认管理员密码仍为 `admin`，部署公网前务必修改。

## 三种部署模式

进入 **设置 → 部署模式与机房身份**，保存后动态生效，不需要更换程序。

| 模式 | 作用 |
| --- | --- |
| 单机 | 只管理当前局域网的选手机；不连接云端。 |
| 并机 | 机房中转。填写机房名、云端根地址和连接密钥，主动通过 WebSocket 连接云端。仍可在机房本地管理。 |
| 云端 | 汇总各中转的机房与设备，通过反向连接发送管理请求；不接受选手机直接注册。 |

```text
云端（HTTPS）
├── A301 中转 ── 本地设备 #1、#2、#3
└── B202 中转 ── 本地设备 #1、#2、#3
```

1. 云端设置为“云端模式”，生成不少于 32 字符的随机连接密钥。
2. 每个机房启动相同的服务端程序，设置为“并机模式”，填写机房名和同一密钥。
3. 机房中转填写自己的局域网 IP，尤其是有多个网卡时。云端地址例如 `https://control.example.com`，不带子路径。
4. 选手机仍连接本机房中转的 TCP 端口，不直接连接云端。
5. 云端的“机房总览”仅展示机房连接和拓扑。仪表盘、设备、命令、分发、网络、电源、签到、广播均保留独立页面，与单机模式保持一致的导航。顶部范围选择器支持全部机房 / 单个机房，切换范围不会跳回机房总览。
6. 全部机房范围下可查看汇总统计、设备及最近命令，使用“机房 + 设备号”选择目标统一操作、导出 CSV。切换到具体机房可使用完整设备详情、交互终端、命令历史、签到和电源计划管理。

屏幕监控流仅在机房本地访问，不通过云端中转；服务端同时拒绝云端屏幕代理请求。**广播内容不是屏幕监控流**：支持云端编辑、预览、同步素材，并由中转在本机房分发、展示。

每个中转拥有持久化 UUID。云端设备身份为 **中转 UUID + 机房内设备号**，不同机房可以使用相同数字编号。设置中的“设备号起点”仅作用于新设备，不会重新编号已有设备。新建机房应使用独立工作目录与新数据库，**不要直接复制另一机房的数据库**。

切换为云端模式会断开本地选手机。运行中的分发必须先停止，才能更改部署配置。云端的待投递任务会保存在数据库中；切换模式不会自动删除它们。

### 网络与安全

- 公网仅暴露 HTTPS 管理入口，反向代理需支持 WebSocket Upgrade。机房只需要能主动访问云端，不需要开放入站公网端口。
- 云端建议使用 `--avahi=false`。不要向公网开放选手机 TCP/P2P 端口；这些协议用于可信机房内网，不提供公网身份认证。
- 默认本地端口：管理 HTTP `8080`、选手机控制 TCP `8081`、P2P 源站 TCP `48080`；选手机之间的 P2P 监听端口为 `3000–3998`。
- 仅可信内网测试时勾选“允许 HTTP”；公网使用 HTTPS 和强管理员密码。连接密钥属于高权限凭据，应妥善保管、定期更换。
- 多个实例运行在同一主机时，为每个实例使用不同工作目录、数据库、HTTP/TCP/P2P 端口。
- 云端离线投递队列仅在显式选择设备并确认后创建。任务可在尚未投递时取消；已投递操作应在对应机房中检查、取消。
- “已接收”仅表示中转接受请求，**不代表机器执行成功**。命令结果看机房命令日志；文件结果看每个文件、每台设备的校验回执。
- 中转持久化请求回执，断线重送同一请求不会再次执行。若中转在执行与落盘之间崩溃，结果会标为待核实，不自动重复危险操作。

## 设备重号修复

原逻辑会仅凭客户端缓存的数字编号复用离线设备记录；系统镜像复制后，多台机器可能携带相同编号。另外，新记录的 MAC 要等系统信息上报后才写入，存在注册窗口。

现在客户端优先选择物理网卡，结合硬件 UUID 与 MAC 生成身份指纹；服务端在原子分配编号时立即存储身份，以唯一索引约束。数字编号只作显示，不再作为身份凭证。旧数据库中唯一匹配的 MAC 记录会迁移保留编号。不同硬件指纹即便报告相同 MAC，也不会合并。

完全克隆硬件 UUID 和 MAC 的虚拟机仍需要在虚拟化平台配置不同的硬件身份。已有历史错误记录不会自动删除，以免丢失签到和审计数据；确认后可在设备管理移除离线旧记录。

## 文件分发

- 云端通过 HTTPS 向每个机房传一份文件，中转支持 Range 断点续传、SHA-256 缓存复用与校验，再启动机房内 P2P。
- 分块并发下载、坏节点回退源站、校验分块长度和 CRC、检查落盘错误；完整文件 `fsync` 和 SHA-256 校验成功后原子替换目标文件。
- 断点元数据按文件内容摘要隔离，避免同名、同尺寸的新文件错误复用旧进度；恢复分块重新计算校验值。
- 每次发送有独立传输标识，旧文件或旧尝试的进度不会更新新文件；回执中的设备号以实际连接身份为准。
- 每个目标最多自动尝试 3 次；有未确认设备时任务显示失败，不再误报全部完成，也不会跳过失败文件继续下一文件。
- 默认“全部设备”包含本机房已登记的离线设备，离线目标会明确列为未送达；可显式选择在线设备进行分发。
- 分发记录持久化在 `data/distribution-task.json`。重启后的未完成任务标为失败，可点击“补传全部缺失文件”；已确认的文件/设备组合会跳过。
- 后置命令仅在全部文件到达该设备后执行。客户端持久化执行回执，不自动重复已执行但结果不确定的后置命令；此时应人工核实后新建任务。
- 分发期间禁止通过管理 API 覆盖或删除源文件。运行中的任务文件不要通过操作系统手动更改。

## 广播管理

页面/图层列表、画布、元素属性统一为三栏工作区，小屏自动折叠布局。支持页面复制、上下移动排序、自动选中页面、未保存修改提醒。字体管理收纳在可折叠区，避免挤占画布空间。页面属性保存不会再重置轮播顺序。

画布拖动自动保存位置；标题、文字及样式修改使用对应的保存按钮。展示页保留原有画面样式，管理页与其他功能共享深浅色主题。

云端广播发布流程：

1. 在“广播”页编辑统一内容并保存，显式选择一个或多个目标机房（也可选择全部）。
2. “仅同步内容与素材”替换目标机房的赛前 / 赛中 / 赛后页面、图片、字体与共享配置，不启动或关闭已有广播。“推送到选手机”会先同步，再由各中转启动当前模式的广播；关闭和复位也按所选机房投递。
3. 机房本地设置的广播推送地址始终保留。请在每个机房本地“广播 → 推送地址”填写选手机可访问的中转局域网 HTTP 地址（含实际端口）；云端地址不会替换此地址。
4. 发布采用持久化队列，离线机房恢复后继续投递。图片与字体按 SHA-256 冻结保存并校验，素材全部到齐才事务性替换内容；下载失败可重试，重复或旧版本不会重复启动或覆盖新版本。
5. 保存只修改云端草稿，再次修改后需要再次同步 / 推送。同步会覆盖目标机房本地编辑的内容，请先备份。新版本需要同时升级云端和各中转。

发布素材保存在 `data/broadcast/releases/`，以保证排队期间编辑、删除原素材不影响已发布版本；这些文件包含在广播备份中。不要在有待投递任务时手动清理。删除页面元素不会删除可能仍由其他页面引用的图片。

## 导出、备份与恢复

设置页提供：

- 设备和签到 Excel、机房设备 CSV。
- 全部业务数据 JSON（不含管理员密码散列、机房连接密钥和登录签名密钥）。
- 配置与数据 ZIP：SQLite 一致性快照、广播素材、分发记录、SHA-256 清单。
- 完整 ZIP：额外包含上传的分发文件。

ZIP **包含敏感凭据和学生信息**，应加密存放。备份使用 SQLite `VACUUM INTO`，不是直接复制可能尚未合并 WAL 的数据库文件。

恢复必须停机，在原服务工作目录执行：

```bash
# 先停止服务；以下只是例子，请替换真实服务名称与路径
sudo systemctl stop icpc-server
./server --db icpc.db --restore /path/to/backup.zip
sudo systemctl start icpc-server
```

恢复先验证 ZIP 路径、文件 SHA-256 和 SQLite 完整性，通过后才替换数据；原数据库及数据目录保留为 `.pre-restore-时间戳`。恢复命令本身不会启动服务。解压大小上限为 50 GiB。

不含分发文件的备份恢复后，原上传文件仍在旧的 `.pre-restore-*` 目录中，可按需手动迁回。备份应恢复到原机房身份；不要把同一备份同时用于多个新机房。

`data/` 相对于程序工作目录，`--db` 指定数据库路径；恢复时请使用相同工作目录。迁移到不同文件系统时应先把备份与目标数据准备到同一文件系统，避免目录原子替换失败。

## 验证

```bash
go test -race ./...
go vet ./...
make test-p2p
```

回归测试覆盖并发编号、镜像复制编号、旧身份迁移、两机房同号设备隔离、请求去重、屏幕隔离、离线队列、断点缓存、分发误报、损坏分块恢复、多客户端 P2P、广播复制、广播离线发布与素材校验、旧版本防覆盖、局域网地址保留和备份恢复。

内嵌 `pkg/go-silver-core/test/` 中的原有演示测试仍使用旧版接口，直接在该子模块运行 `go test ./...` 会出现既有编译错误；`test-p2p` 运行当前库与新增回归测试，不修改这些旧演示。

1. 改造总览与原则

审计结论：功能面已远超原始需求，但赛场可靠性被四条链路拖垮——大屏空白、在线状态不可信、 客户端断线 panic、分发完成态卡死。本轮只修「体验与稳定性」，不引入 JWT/mTLS 等安全项。

优先级原则

  • P0：会直接导致赛场事故（空白大屏、假离线、客户端崩溃、分发永不结束）
  • P1：每天用的控制台体验（整页刷新打断、进度不可读、跨网段看不了屏）
  • P2：升级项（断点续传、导航分组、多机房子网策略）
改造前痛点

广播鉴权后空白；Hub 重连踢新连接；客户端 send panic；P2P progressCh 永不 close；设备事件整页重刷；屏幕直连选手 IP。

改造后状态

大屏 WS 快照 + 只读 API；Hub 指针安全注销；safeSender；progress 必 close + 超时 stall；防抖局部更新；屏幕服务端反代。

2. Sprint 1 — 赛前阻断 S1 · 必做

先保证「能用、不崩、状态可信」。

2.1 Hub 重连竞态 + 在线枚举

修复 internal/biz/hub.go

改动说明
Unregister 指针相等仅当 h.clients[id] == client 时删除，避免旧连接注销误删新连接
Register 替换旧连接关掉旧 TCP 并 close(old.Send)，写泵可退出
OnlineIDs()取代分发里 for i := 1; i <= 200 硬编码扫描
TrySend()非阻塞发送，缓冲满时不挂死调度协程

验收：客户端快速重连 10 次，后台始终在线且命令可下发。

2.2 客户端 send 生命周期 / 签到 / fastfetch / 清理

修复 cmd/client/main.go · watermark.go

  • 引入 safeSender：加锁 + closed 标志，禁止向已关闭 channel send（根治 panic）
  • 签到 / 签退：sender == nil 时返回「设备当前离线」JSON，不再崩溃
  • collectSystemInfo：fastfetch 失败发送最小合法 system_info stub，避免被服务端踢线死循环
  • 断线 cleanupClientProcesses：Kill 命令进程组 + 关闭终端 PTY
  • 启动时创建空 ~/server（对齐需求）；IPv6 友好 ensurePort；hostnamectl 失败打日志
  • 命令输出 Scanner 缓冲扩至 1MB，减少长行丢失

2.3 广播大屏首次有内容

修复 broadcast_ws.go · broadcast_handler.go · auth_handler.go · display.js

  • WS Serve 连接后立刻用 SnapshotProvider 推 pages_updated
  • 每连接独立 write mutex，避免 carousel / 推送并发写导致断流
  • GET 只读：pages / config / fonts / countdown 免登录（大屏选手机无需 JWT）
  • 字体/图片路径 filepath.Base
  • display.js：重连清理 ping 定时器；滚动字幕 scaleFont

验收：未登录打开 /broadcast/before，数秒内显示当前页。

2.4 P2P 完成态 + 任务不卡死

修复 gosilver.go · receiver.go · conn_pool · distribution.go

  • runDownload defer closeProgress()：终端态后 channel 关闭，客户端 for range 退出，post_cmd 可执行
  • RPC：nil 检查 + dial/读写超时；坏连接 DiscardConn 不回池
  • PeerReg 独立 dial，不再永久占用连接池槽位
  • 分发 wait：单文件 30min 超时；3min 无进度标 stalled
  • 目标列表 OnlineIDs()；进度 hostname 经 SetHostnameLookup 查库
  • 文件名 Base + 存在性校验；非阻塞 TrySend

2.5 前端致命交互

修复 terminal.js · app.js · commands.js

  • 终端 modal 独立 id，关闭不再 $(".modal-overlay").remove() 误关设备详情
  • 设备 WS 事件防抖 400ms + 优先局部更新
  • 命令历史 summary escapeHtml（体验向的输出展示安全）
  • isActiveEvent 仅认本批次 cmdIds，避免进度串台

3. Sprint 2 — 明显好用 S2 · 好

控制台「不打断」、看板可用、分发可读、屏幕跨网段可用。

3.1 Toast + 局部刷新

  • 全局 showToast(msg, type) + CSS（success / error / info）
  • 设备表：data-device-id + patchDevicesFromEvent
  • 签到：弹窗打开时只刷统计，避免冲掉表单
  • 网络页：事件不再强制整页 loadNetwork()

3.2 看板聚合

dashboard.js 重写：

  • 统计卡：总数 / 在线 / 离线 / 已签到 / 未签到 / 命令数，可点击跳转
  • 「进行中任务」：分发状态、当前文件、平均进度、完成/失败数
  • 快捷入口：广播 / 网络 / 屏幕
  • WS 触发 patchDashboardStats / patchDashboardTasks，非整页替换

3.3 分发 UI 可读

  • 总体进度 = 各机 percentage 平均（非仅完成台数）
  • 失败 / stalled 行置顶；可重试 stalled / cancelled
  • 多文件显示「第 i/n 个文件」
  • 步骤编号修正（去掉跳号）；文案去掉误导性「分块上传」
  • 列表显示真实 hostname（服务端注入）

3.4 屏幕监控服务端反代

新增 screen_proxy_handler.go · 路由 GET /api/devices/{id}/screen

Before

浏览器直连 http://选手IP:8090/screen — 跨 VLAN/NAT 失败，HTTPS 混内容。

After

管理端同源 /api/devices/{id}/screen，服务端按设备 IP 反代 MJPEG/单帧。

screen.js 缩略图与 HD 弹窗全部改走 proxy；iOS 轮询亦使用 device id。

3.5 命令体验

  • 按钮「重跑失败机」：收集 failed/timeout 的 deviceId 再执行
  • 批次事件归属收紧，避免并发下发串结果

3.6 杂项可靠性

  • 尊重 --avahi / cfg.Avahi；stop 时 Wait 防僵尸进程
  • HTTP WriteTimeout: 0，避免长 WS / 屏幕流被切断
  • 设备 formatDateTime pad 笔误修正

4. Sprint 3 — 体验升级 S3 · 增强

断点续传、终端重连、导航分组、多机房 P2P 策略。

4.1 分发断点续传

gosilver.runDownload：

  • 同名文件且 size 匹配时 Open 而非 Create 清空
  • 元数据文件 *.icpc-chunks 记录已完成 chunk 索引
  • 失败/取消保留 part + meta；完成删除 meta
  • 已完成 chunk 跳过下载并重新 Report 给 tracker 供 P2P

4.2 终端增强

  • 断线提示 +「重连」按钮
  • window.resize → fit addon
  • 独立 overlay，不干扰其他弹窗

4.3 导航分组

index.html 顶栏按运维场景分组：

监控：仪表盘 · 设备 · 屏幕
运维：命令 · 网络 · 分发
比赛：签到 · 广播
系统：设置 · 退出

4.4 P2P 多机房子网策略

  • PeerSelectMode：subnet（同 /24）或 all（任意 peer）
  • 环境变量 ICPC_P2P_PEER_MODE=subnet|all
  • 默认 all，适配多 VLAN 机房（避免全部打回 seeder）

7. 明确未做项（本轮范围外）

  • JWT 密钥随机化、强制改默认密码、TCP/GSP 认证、mTLS
  • SaveDir / post_cmd 沙箱与命令白名单
  • 整文件 SHA-256 校验、CORS / CSP 收紧
  • 前端框架重写、构建工具链、完整自动化测试套件

上述项属于安全或下一阶段 polish；若威胁模型从「纯内网」变为「可达外网 / 访客 Wi‑Fi」，应优先做控制面认证。

✓ 结论

Sprint 1–3 体验向改造已全部落地，主路径编译通过。 赛场最伤的四条链路（大屏、在线状态、客户端通道、分发完成态）已处理； 控制台局部刷新、屏幕反代、看板与分发可读性显著提升。 建议按第 6 节清单在实机 / 模拟机房跑一轮回归后再上场。
